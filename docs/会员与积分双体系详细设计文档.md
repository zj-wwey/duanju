## 1. 文档概述

### 1.1 目标

设计一套会员与积分双体系，确保两个体系既能独立运行又能协同工作，涵盖会员等级、积分获取/消费、积分有效期、关联机制、积分购买、自动续费等完整业务链路，为后续开发提供完整需求依据。

### 1.2 设计原则

- 会员与积分双体系独立运行，通过倍率、折扣、兑换等机制协同
- 所有积分变动通过 `PointService.addPoints()` 统一入口（R10）
- Service 层依赖关系为 DAG（有向无环图），无循环依赖
- 数据库迁移通过 `SchemaMigrationRunner` 幂等执行，无破坏性 DDL
- 所有业务逻辑在 Service 层，Controller 仅做参数校验和路由

## 2. 现有系统分析

### 2.1 现有能力

| 模块 | 现有能力 | 关键类 |
|------|---------|--------|
| 会员 | `UserVipRecord` 记录 VIP 开通/过期，`packageType` 区分类型 | `VipService` |
| 积分 | 签到(+5)、广告(+2)、管理员调整、购买获取；解锁剧集/整剧消费 | `PointService` |
| 商品 | `PointProduct` 同时承载 VIP 套餐和积分充值包 | `PointProductService` |
| 解锁 | `UnlockService` 仅支持积分解锁 | `UnlockService` |
| 订单 | 支持 Stripe/PayPal/Apple IAP/Google Play 四渠道 | `OrderService` |

### 2.2 现有问题

| 问题 | 影响 |
|------|------|
| `VipService.activateVip()` 已实现但从未被 `OrderService` 调用 | 购买 VIP 套餐后只发积分，不激活会员 |
| 无会员等级体系 | 无法实现差异化权益 |
| 积分无有效期 | 赚取积分永久有效，无法过期清理 |
| VIP 无解锁权益 | VIP 用户看剧仍需扣积分 |
| 积分无倍率 | 会员无积分加成 |
| 商品分类混淆 | `packageType` 混用充值/VIP，前端过滤逻辑脆弱 |
| 无购买限制 | 可无限购买 |
| 无累计消费字段 | 无法实现消费升级 |

## 3. 会员体系设计

### 3.1 等级划分

| 等级 | 标识 | 名称 | 升级条件 |
|:---:|:---:|------|---------|
| L0 | NONE | 普通用户 | 注册即享 |
| L1 | SILVER | 银牌会员 | 累计消费 >= ¥99 或购买银牌套餐 |
| L2 | GOLD | 金牌会员 | 累计消费 >= ¥299 或购买金牌套餐 |
| L3 | DIAMOND | 钻石会员 | 累计消费 >= ¥999 或购买钻石套餐 |

**升级规则：**

- **消费升级**：累计支付金额达到阈值自动升级，**永久保级不降级**（消费金额只增不减）
- **购买升级**：直接购买对应等级会员套餐，有效期结束后回退到消费等级
- **等级取高原则**：同时满足多个条件时取最高等级

### 3.2 等级判定逻辑

```
当前等级 = max(消费等级, 购买等级)

消费等级（根据 total_spent_cents，永久保级）:
  >= 99900 分(¥999) → DIAMOND
  >= 29900 分(¥299) → GOLD
  >= 9900  分(¥99)  → SILVER
  else              → NONE

购买等级（根据 purchase_level + purchase_expire_at）:
  purchase_expire_at > now → purchase_level
  else → 不参与（已过期）
```

### 3.3 各等级权益

| 权益项 | 普通用户 | 银牌会员 | 金牌会员 | 钻石会员 |
|--------|:------:|:------:|:------:|:------:|
| 每日免费观剧集数 | 3集 | 8集 | 15集 | 30集 |
| 积分获取倍率 | 1.0x | 1.2x | 1.5x | 2.0x |
| 单集解锁折扣 | 无 | 9.5折 | 9折 | 8.5折 |
| 整剧解锁折扣 | 无 | 9折 | 8折 | 7折 |
| 去广告 | 无 | 无 | 部分（去插播） | 全部 |
| 离线缓存 | 0部 | 3部 | 10部 | 无限 |
| 弹幕颜色 | 白色 | 白色 | 金色 | 金色+发光特效 |
| 专属客服 | 无 | 无 | 有 | 有 |
| 生日礼包 | 0积分 | 50积分 | 100积分 | 200积分 |
| 商城兑换优惠 | 无 | 无 | 无 | 专属优惠价 |

### 3.4 会员套餐

| 套餐 | 银牌 | 金牌 | 钻石 |
|------|:---:|:---:|:---:|
| 月卡 (30天) | $2.99 | $4.99 | $7.99 |
| 季卡 (90天) | $7.99 | $12.99 | $19.99 |
| 年卡 (365天) | $26.80 | $42.80 | $66.80 |

### 3.5 开通/续费机制

**续费规则：**

| 场景 | 规则 |
|------|------|
| 同等级续费 | 剩余天数直接叠加，不覆盖已有有效期 |
| 跨等级升级 | 旧等级剩余天数按价格比折算为新等级天数，旧记录标记失效 |
| 到期后续费 | 从购买日起算新周期 |

**升级折算比例表：**

| 旧等级 → 新等级 | 折算比例 | 说明 |
|:---:|:---:|------|
| SILVER → GOLD | 0.6 | 银牌1天 ≈ 金牌0.6天 |
| SILVER → DIAMOND | 0.4 | 银牌1天 ≈ 钻石0.4天 |
| GOLD → DIAMOND | 0.65 | 金牌1天 ≈ 钻石0.65天 |

折算比例基于各等级月卡日均价格比计算：
- SILVER 月卡 $2.99 → 日均 $0.0997
- GOLD 月卡 $4.99 → 日均 $0.1663
- DIAMOND 月卡 $7.99 → 日均 $0.2663

### 3.6 退款规则

- 购买 7 天内且观看解锁少于 10 集 → 可申请退款
- 购买 7 天后或观看超过 10 集 → 不支持退款
- 退款后会员权益立即失效，已使用的积分获取加成不追回
- 退款扣回基础积分，减少累计消费金额（但不降级消费等级）

### 3.7 自动续费

| 配置项 | 规则 |
|--------|------|
| 扣款时机 | 会员到期前 24 小时自动扣款 |
| 支付渠道 | Stripe（payment_method_id）、PayPal（billing_agreement_id） |
| 失败重试 | 扣款失败延后 6 小时重试 |
| 取消条件 | 连续失败 3 次自动取消订阅 |
| 用户操作 | 可随时取消，取消后当前周期内仍享权益 |

## 4. 积分体系设计

### 4.1 积分获取途径

| 途径 | 基础积分 | 频次限制 | 倍率 | bizType |
|------|:------:|---------|:---:|---------|
| 每日签到 | +5 | 每日1次 | ✅ | CHECKIN |
| 连续签到7天 | +10 | 每7天1次 | ✅ | CHECKIN |
| 观看广告 | +2 | 每日10次，30秒冷却 | ✅ | AD_REWARD |
| 看完一集 | +1 | 每日20集 | ✅ | EPISODE_WATCH |
| 分享剧集 | +3 | 每日5次，需好友点击确认 | ✅ | SHARE |
| 邀请好友 | +50 | 无上限，好友完成首次观看后发放 | ✅ | INVITE |
| 观看时长 | +1/10分钟 | 每日上限30积分 | ✅ | WATCH_DURATION |
| 优质评论 | +5~20 | 每日3次 | ✅ | COMMENT |
| 生日礼包 | 50/100/200 | 每年1次 | ❌ | BIRTHDAY |
| 活动赠送 | 按活动 | 按活动 | ❌ | PROMOTION |
| 购买积分 | 按套餐 | 见第6章 | ❌ | RECHARGE |

**签到连续奖励机制：**

- 连续签到天数通过 `user_checkin.consecutive_days` 追踪
- 每日签到时查昨日记录计算连续天数
- 每 7 天（第7天、第14天、第21天...）额外奖励 10 积分

**分享真实性检测：**

- 分享后标记为 PENDING，24 小时内有效
- 好友通过分享链接访问该剧集时触发确认发放
- 同一剧集每日只奖励一次
- 两次分享至少间隔 60 秒

**邀请好友流程：**

1. 用户生成邀请链接/邀请码
2. 好友通过链接注册，创建 `user_invite` 记录（status=PENDING）
3. 好友完成首次观看，触发 `onInviteeFirstWatch()`
4. 邀请人获得 50 积分

### 4.2 积分消费场景

| 场景 | 消费规则 | 说明 |
|------|---------|------|
| 解锁单集 | 按集定价(50-200积分)，会员享折扣 | VIP可使用每日免费额度 |
| 解锁整剧 | 按剧定价(500-2000积分)，会员享折扣 | 已解锁集数自动抵扣，最低50% |
| 积分兑换会员 | 按兑换价格表 | 同等级续费享9折 |
| 商城兑换 | 兑换实物/虚拟道具 | 钻石会员享专属优惠价 |
| 高级弹幕 | 10积分/条 | 彩色/特效弹幕收费，普通白色免费 |

**整剧解锁抵扣规则：**

| 情况 | 计算方式 |
|------|---------|
| 未解锁任何集数 | 整剧原价 × VIP折扣 |
| 已解锁部分集数 | (整剧原价 - 已花费) × VIP折扣 |
| 已花费 >= 整剧价50% | 整剧原价 × 50% × VIP折扣 |
| 已花费 >= 整剧价 | 0（直接标记解锁） |

### 4.3 积分有效期规则

| 积分来源 | 类型 | 有效期 | FIFO优先级 |
|---------|------|:------:|:--------:|
| 签到/广告/观看/分享/邀请等 | EARNED | 获取后12个月 | 2 |
| 购买积分包 | PURCHASED | 永久有效 | 3 |
| 活动赠送/运营补偿 | PROMOTION | 默认3个月（可自定义） | 1 |

**过期规则：**

- 消费积分时按 FIFO 顺序消耗：PROMOTION → EARNED → PURCHASED
- 每月1日 00:30 自动清理过期积分
- 清理时扣减 `app_user.points`，写入 `PointRecord(bizType=EXPIRE)`

### 4.4 积分兑换会员

| 兑换项 | 基础价格 | 同等级续费价(9折) |
|--------|:------:|:------:|
| 银牌会员 1天 | 200积分 | 180积分 |
| 银牌会员 7天 | 1200积分 | 1080积分 |
| 金牌会员 1天 | 350积分 | 315积分 |
| 金牌会员 7天 | 2100积分 | 1890积分 |
| 钻石会员 1天 | 600积分 | 540积分 |
| 钻石会员 7天 | 3600积分 | 3240积分 |

**限制：** 积分兑换的会员天数不计入累计消费金额（R6）。

## 5. 会员与积分关联机制

### 5.1 会员影响积分获取

```
实际获得积分 = 基础积分 × 会员等级倍率（向上取整）
```

**示例：**

| 行为 | 基础值 | 银牌(1.2x) | 金牌(1.5x) | 钻石(2.0x) |
|------|:---:|:---:|:---:|:---:|
| 签到 | +5 | +6 | +8 | +10 |
| 广告 | +2 | +3 | +3 | +4 |
| 看完一集 | +1 | +2 | +2 | +2 |

**实现要点：**
- 倍率在 `PointService.addPoints()` 内部自动应用
- 退款(`ORDER_REFUND`)、管理员调整(`ADMIN_ADJUST`)不应用倍率
- `addPoints()` 返回倍率信息供前端 Toast 展示

### 5.2 会员影响积分消费

- 单集/整剧解锁享受折扣
- 折扣计算：`实际扣减 = 原价 × 折扣率（向上取整）`
- 商城兑换：钻石会员享专属优惠价

### 5.3 积分辅助会员成长

- 购买积分 → 累计消费金额增加 → 达到阈值 → 永久升级会员等级
- 积分兑换会员体验天数 → 体验权益 → 付费转化
- 个人中心展示"距下一级还需消费 $XX"

## 6. 积分购买功能设计

### 6.1 价格体系

| 套餐 | 基础积分 | 赠送积分 | 实得积分 | 价格(USD) | 首充额外赠送 |
|------|:------:|:------:|:------:|:------:|:------:|
| 迷你包 | 100 | 0 | 100 | $0.99 | +20 |
| 基础包 | 500 | 50 | 550 | $4.99 | +100 |
| 进阶包 | 1200 | 180 | 1380 | $9.99 | +240 |
| 豪华包 | 3000 | 600 | 3600 | $24.99 | +600 |
| 至尊包 | 6000 | 1500 | 7500 | $49.99 | +1200 |

**首充优惠：** 用户首次购买任意积分包，额外赠送 20% 基础积分（仅一次）。

### 6.2 购买限制

| 限制项 | 规则 | 实现 |
|--------|------|------|
| 单次购买 | 每种套餐每次限购1份 | - |
| 每日限购 | 每种套餐每日3次（可配置） | `point_product.daily_limit` |
| 每月限购 | 按套餐配置（见种子数据） | `point_product.monthly_limit` |
| 全局月上限 | 所有套餐合计每月不超过 $5000 | 硬编码 |
| 新用户限制 | 注册<24h限购$4.99以下+每日1次 | 运行时判断 |
| 未成年限制 | 月累计不超过 $200 | 实名认证 |

**默认限购配置：**

| 套餐 | daily_limit | monthly_limit |
|------|:---:|:---:|
| 迷你包 | 3 | 30 |
| 基础包 | 3 | 30 |
| 进阶包 | 3 | 15 |
| 豪华包 | 2 | 10 |
| 至尊包 | 1 | 5 |
| VIP月卡 | 3 | 12 |
| VIP季卡 | 3 | 4 |
| VIP年卡 | 1 | 2 |

### 6.3 购买流程

```
用户选择套餐
  → 确认订单（展示积分明细、价格、会员倍率提示、等级变化预告）
  → 购买限制校验（日限/月限/全局上限/新用户/未成年）
  → 选择支付方式
  → 调用支付网关
  → 支付成功
    → 积分即时到账（写入 point_expire 批次）
    → 累计消费金额更新（total_spent_cents）
    → VIP类商品激活会员（vipService.activateVip）
    → 检查是否触发消费升级（membershipService.onPaymentSuccess）
    → 发送通知
    → 记录 PointRecord(bizType=RECHARGE)
```

**异常处理：**

- 支付超时/取消：订单标记为已取消，不扣款不发放
- 支付成功但积分发放失败：订单持久化 + 重试队列补偿
- 重复支付：基于 orderNo 唯一约束幂等处理

## 8. 数据库设计

### 8.1 新增表

#### 8.1.1 user_membership（会员等级表）

```sql
CREATE TABLE IF NOT EXISTS user_membership (
  id                   BIGINT PRIMARY KEY AUTO_INCREMENT COMMENT 'ID',
```

### 10.2 PointService（重构）

**新增依赖：** `MembershipService`、`PointExpireService`

**addPoints() 重构：**

```java
@Transactional
public Map<String, Object> addPoints(Long userId, int delta, String bizType, String bizId, String remark) {
    int originalDelta = delta;
    int actualDelta = delta;
    double multiplier = 1.0;
    String level = "NONE";

    // 1. 正向积分：应用会员倍率
    if (delta > 0 && shouldApplyMultiplier(bizType)) {
        level = membershipService.getCurrentLevel(userId);
        multiplier = membershipService.getPointMultiplier(level);
        actualDelta = (int) Math.ceil(delta * multiplier);
    }

    // 2. 扣减积分：FIFO消耗
    if (actualDelta < 0) {
        pointExpireService.consumePoints(userId, -actualDelta);
    }

    // 3. 更新余额
    if (!userService.changePoints(userId, actualDelta)) {
        throw new IllegalArgumentException("insufficient points or user not found");
    }

    // 4. 正向积分：写入过期批次
    if (actualDelta > 0 && shouldApplyMultiplier(bizType)) {
        boolean isPurchased = "RECHARGE".equals(bizType) || "ADMIN_ORDER_PAY".equals(bizType);
        pointExpireService.createBatch(userId, actualDelta, isPurchased ? "PURCHASED" : "EARNED");
    }

    // 5. 记录流水
    recordPoint(userId, actualDelta, bizType, bizId, remark);

    // 6. 返回倍率信息
    return MapUtil.map(
        "original_delta", originalDelta,
        "actual_delta", actualDelta,
        "multiplier", multiplier,
        "bonus_delta", actualDelta - originalDelta,
        "membership_level", level,
        "has_bonus", actualDelta > originalDelta,
        "user", userService.getProfile(userId)
    );
}

// 不应用倍率的业务类型
private boolean shouldApplyMultiplier(String bizType) {
    return !Set.of("ORDER_REFUND", "ADMIN_ADJUST", "ADMIN_ORDER_PAY", "PROMOTION", "BIRTHDAY").contains(bizType);
}
```

```java
@Transactional
public Map<String, Object> checkin(Long userId) {
    LocalDate today = LocalDate.now();
    // ... 签到去重检查 ...

    // 查昨日记录计算连续天数
    UserCheckin yesterday = userCheckinService.lambdaQuery()
            .eq(UserCheckin::getUserId, userId)
            .eq(UserCheckin::getCheckinDate, today.minusDays(1))
            .one();
    int consecutiveDays = yesterday != null ? yesterday.getConsecutiveDays() + 1 : 1;

    // 基础积分 + 连续7天奖励
    int basePoints = CHECKIN_POINTS;  // 5
    int bonusPoints = 0;
    if (consecutiveDays % 7 == 0) {
        bonusPoints = 10;
    }
    int totalPoints = basePoints + bonusPoints;

    UserCheckin checkin = new UserCheckin();
    checkin.setUserId(userId);
    checkin.setCheckinDate(today);
    checkin.setPointDelta(totalPoints);
    checkin.setConsecutiveDays(consecutiveDays);
    userCheckinService.save(checkin);

    // 走统一入口，应用会员倍率
    Map<String, Object> pointResult = addPoints(userId, totalPoints, "CHECKIN", today.toString(), "daily checkin");

    return MapUtil.map(
        "user", pointResult.get("user"),
        "consecutive_days", consecutiveDays,
        "base_points", basePoints,
        "bonus_points", bonusPoints,
        "membership_multiplier", pointResult.get("multiplier"),
        "membership_bonus", pointResult.get("bonus_delta"),
        "total_earned", pointResult.get("actual_delta")
    );
}
```

### 10.3 PointExpireService（新增）

**FIFO 消费排序：**

```sql
ORDER BY 
  CASE point_type 
    WHEN 'PROMOTION' THEN 1 
    WHEN 'EARNED' THEN 2 
    WHEN 'PURCHASED' THEN 3 
  END,
  expire_at ASC
```

**过期时间规则：**

| point_type | expire_at |
|------------|-----------|
| EARNED | today + 365天 |
| PURCHASED | 9999-12-31 |
| PROMOTION | today + 90天（默认）或自定义 |
