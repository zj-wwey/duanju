视频播放界面重设计方案

参照抖音布局 · 9:16 竖屏 + 16:9 横屏 · 完整实施规格

一、当前问题分析

通过对 player_overlay.nvue、index_overlay.nvue、player.vue、index.vue 的代码分析，当前界面存在以下核心问题：

问题1：图标/文字极小
右侧操作栏图标仅 24rpx，标签仅 12rpx，在手机上几乎看不清
当前：icon 24rpx / label 12rpx
问题2：暗色方块容器
操作按钮包裹在 rgba(12,13,18,0.55) 的暗色方块里，不符合抖音的无背景透明风格
当前：52rpx 暗色圆角方块
问题3：底部信息字号小
标题 22rpx、描述 16rpx、集数文字 16rpx，在竖屏视频上缺乏层次感
当前：title 22rpx / desc 16rpx
问题4：全宽暗色底栏
底部集数栏是全宽暗色条 rgba(0,0,0,0.55)，不是抖音的浮动透明胶囊样式
当前：height 52rpx 全宽暗色
问题5：文字无阴影
subNVue 中的文字没有 text-shadow，在亮色视频画面上完全看不清
当前：无 text-shadow
问题6：间距不足
按钮间距仅 12rpx，操作区整体拥挤，底部信息与右侧操作栏可能重叠
当前：margin-bottom 12rpx

二、设计原则（参照抖音）

透明无框
操作按钮无背景容器，纯图标+文字+阴影，与视频画面融合
大号清晰
图标 ≥48rpx，文字 ≥22rpx，确保在手机上清晰可读
文字阴影
所有叠在视频上的文字都加 text-shadow，保证任意画面下可读
底部浮动
集数选择改为胶囊式浮动元素，不是全宽暗色底栏
渐变遮罩
顶部和底部加半透明渐变遮罩，提升文字可读性，不遮挡画面
右侧操作栏
5个操作按钮垂直排列，位于屏幕右下40%区域，间距充裕

五、9:16 竖屏布局详细方案 9:16

竖屏视频占满全屏，所有 UI 元素叠加在视频之上。以下为各区域的精确定位：

5.1 层级结构（z-index 从底到顶）

Layer 0: <video> 全屏 (object-fit: cover, controls: false) Layer 1: <cover-view class="video-tap-area"> 点击暂停/播放（全屏透明） Layer 2: subNVue overlay (透明背景, pointer-events: none) ├─ 渐变遮罩 (顶部 + 底部, pointer-events: none) ├─ 顶部导航栏 (分类标签 + 浏览/我的) ├─ 右侧操作栏 (5个按钮, 垂直排列) ├─ 底部信息 (标题 + 描述 + 集数胶囊) ├─ 进度条 (超薄金色渐变线) └─ (仅player) 返回按钮 Layer 3: app-tab-bar 底部导航 (独立组件, 不在overlay内)

5.2 各区域定位坐标（以屏幕底部为基准）

区域 position top / bottom left / right 尺寸 适用页面
顶部导航栏 absolute top: 0 (+ safe-area-top) left: 0, right: 0 height: 88rpx index
返回按钮 absolute top: calc(16rpx + safe-area-top) left: 16rpx 56×56rpx, icon 48rpx player
右侧操作栏 absolute bottom: 280rpx (+ safe-area-bottom) right: 16rpx 5项 × (48+22+24)rpx = 470rpx 高 both
底部信息区 absolute bottom: 120rpx (+ safe-area-bottom) left: 24rpx, right: 120rpx title 30rpx + desc 22rpx + pill both
集数胶囊 (index) inline 在底部信息区内 align-self: flex-start padding: 6rpx 16rpx, text 22rpx index
进度条 absolute bottom: 88rpx (+ safe-area-bottom) left: 0, right: 0 height: 4rpx both
底部集数栏 (player) absolute bottom: 0 (+ safe-area-bottom) left: 0, right: 0 height: 56rpx, text 22rpx player
底部导航栏 fixed bottom: 0 left: 0, right: 0 height: calc(80rpx + safe-area-bottom) index
关键点：底部信息区的 right 设为 120rpx（原80rpx），确保标题文字不会延伸到右侧操作栏下方被遮挡。右侧操作栏的 bottom 从 170rpx 提升到 280rpx，因为按钮变大后总高度增加，需要上移以避免与底部信息区重叠。

六、16:9 横屏布局方案 16:9

当视频比例为 16:9 时，在 9:16 竖屏手机上视频会上下留黑（letterbox）。所有 UI 元素需要适配视频区域，而非整个屏幕。

6.1 视频区域计算

参数 计算公式 结果（750×1624rpx 屏幕）
视频宽度= 屏幕宽度750rpx
视频高度= 宽度 × 9/16421.875rpx ≈ 422rpx
上下黑边高度= (屏幕高度 - 视频高度) / 2(1624-422)/2 = 601rpx
视频顶部位置= 黑边高度601rpx from top
视频底部位置= 屏幕高度 - 黑边高度601rpx from bottom

6.3 16:9 适配规则

区域 9:16 定位 16:9 调整方案
顶部导航栏 top: 0 不变，留在屏幕顶部（黑边区域内）
返回按钮 top: safe-area 不变，留在屏幕顶部
右侧操作栏 bottom: 280rpx bottom 改为 calc(视频底部位置 + 10rpx)，即 bottom: calc(601rpx + 10rpx)
底部信息区 bottom: 120rpx bottom 改为 calc(视频底部位置 + 8rpx)，即紧贴视频下边缘
进度条 bottom: 88rpx bottom 改为 calc(视频底部位置)，即在视频下边缘
底部导航栏 bottom: 0 不变，留在屏幕底部（黑边区域内）
实现方式：通过 JavaScript 动态计算视频比例，将 --video-bottom-offset CSS 变量传入 subNVue overlay。9:16 时值为 0，16:9 时值为视频底部到屏幕底部的黑边高度（约601rpx）。所有 bottom 定位值加上此偏移量。

替代方案：如果 subNVue 不支持 CSS 变量，则在 sendOverlayUpdate() 中传入 videoBottomOffset 值，在 overlay 的 :style 绑定中动态设置 bottom。

九、方案总结

本方案的核心改动可以归纳为三个关键词：

放大
图标 24→48rpx（×2），文字 12→22rpx（×1.8），标题 22→30rpx，所有元素全面放大到清晰可读的尺寸
透明化
移除所有暗色方块容器背景，改为纯透明 + text-shadow 的抖音风格，UI 元素与视频画面自然融合
重新布局
调整各区域的 bottom/right/left 定位，确保元素不重叠、不被遮挡，集数栏改为浮动胶囊式，添加渐变遮罩提升可读性
