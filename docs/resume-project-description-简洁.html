项目概述

独立设计与开发的海外短剧流媒体平台，对标 TikTok/Douyin 短剧业务模式。用户可通过移动端App浏览短剧Feed流、观看分集内容、通过积分或会员解锁付费剧集。平台后端提供完整的内容管理、用户运营、支付结算、数据分析能力，管理后台支持内容编排、订单管理、用户管理、数据看板等功能。

核心职责与技术实现

1. 后端架构设计

采用标准 Controller → Service → Mapper 三层分层架构，所有业务逻辑集中在Service层（@Transactional），Controller仅负责参数校验和路由委托。

  • 设计 29个REST控制器，覆盖C端用户API、管理后台API、公开API三类
  • 实现 30+Service类，包含业务编排层和实体数据访问层，依赖关系构成DAG无环图
  • 定义 33个实体类 + 33个Mapper接口，使用MyBatis-Plus BaseMapper简化CRUD
  • 统一 DTO包结构（dto/auth, dto/admin, dto/order, dto/payment等），请求/响应对象分离
  • 全局异常处理器 ApiExceptionHandler 兜底，生产环境不暴露异常原始消息

2. 认证与权限系统

  • 自定义JWT双Token机制：Access Token (7天) + Refresh Token (30天)，使用HmacSHA256签名
  • Redis管理Token状态：Key格式 auth:access:{jti} / auth:refresh:{jti}，支持主动注销
  • RBAC权限注解：自定义 @RequiresPermission("content:manage") 注解，AdminInterceptor校验管理员身份
  • 启动安全校验：密钥长度≥32字符，生产环境禁止弱密钥，环境变量注入所有密钥
  • 多角色体系：SUPER_ADMIN / CONTENT_OPERATOR / USER_OPERATOR 三类角色

3. 多渠道支付集成

统一对接 4种支付渠道，覆盖Web端和移动端全场景：

  • Stripe：Checkout Session创建支付链接，Webhook验签处理支付成功事件
  • PayPal：Orders API创建订单 → Capture捕获 → Webhook回调确认
  • Apple IAP：App Store Server API交易校验，StoreKit通知处理（S2S）
  • Google Play：Google Play Developer API购买验证，RTDN实时通知处理
  • 幂等保障：数据库唯一索引 uk_order_stripe_pi、uk_order_google_purchase_token、uk_order_paypal_payment_id 防止重复发货
  • 统一Webhook入口：/api/webhooks/{channel}/notify 集中处理回调，下游验签
  • 支付事件日志：PaymentEventLogService记录全链路支付事件

4. 视频存储与转码基础设施

  • 存储抽象层：StorageProvider接口 + LocalStorageProvider / R2StorageProvider 双实现，环境变量切换
  • Cloudflare R2：使用 AWS SDK S3 v2 对接，Region.of("auto")，presigned URL直传
  • Cloudflare Stream：视频上传、查询、删除、签名URL生成，Webhook回写转码状态
  • FFmpeg HLS转码：异步线程池 hlsTranscodeExecutor（独立核心数/队列容量配置），CallerRunsPolicy背压
  • 批量上传：VPS中转批量上传服务，支持并发控制与进度查询

5. 会员与积分体系

  • 四级会员：NONE / SILVER / GOLD / DIAMOND，不同积分倍率
  • 积分来源：签到、广告激励、观看时长、分享邀请、评论奖励，统一通过 PointService.addPoints() 入口
  • 积分过期：批次化管理 + 定时清理（每日00:30执行）
  • VIP系统：会员兑换、自动续费订阅（Stripe/PayPal），定时任务每小时处理续费
  • 积分商城：商品管理、兑换、发货、订单管理
  • 解锁机制：单集解锁/整剧解锁，统一 UnlockService.isEpisodeAccessible() 校验

6. 前端多端开发

  • 移动端 (uni-app + Vue 2)：25+页面，uView UI 70+组件，hls.js视频播放，Token自动刷新拦截器，事件驱动状态管理（uni.$emit/$on）
  • 管理后台 (Vue 3 + Vite + Element Plus)：18页面，ECharts数据看板（播放趋势/观众排名/集数到达率），vue-i18n国际化，Composable状态管理，100+API方法封装
  • KYC官网 (Vue 3 + Express)：SSR式BFF架构，Express托管静态文件+SPA fallback，express-rate-limit限流，nodemailer邮件通知
  • 共享层：19种语言JSON翻译文件，货币/格式化/校验工具函数统一复用
  • i18n脚本：翻译同步、导出、导入、校验CLI工具链

7. DevOps与部署

  • Docker Compose编排：5服务（MySQL 8 / Redis 7 / Spring Boot API / Nginx / admin-build），健康检查依赖链
  • Nginx多子域名：srv(API) / dash(管理后台) / web(H5) / cdn(静态资源) / r2(R2代理)，HTTPS TLS 1.2/1.3
  • CORS白名单：仅允许平台子域名跨域，禁止通配符
  • 自动化部署：PowerShell + Shell双平台脚本，支持全量部署和增量热修复
  • 监控：Spring Boot Actuator + Prometheus metrics暴露
  • Cloudflare Tunnel：本地开发隧道调试

8. 定时任务与运维

  • 每小时：会员过期处理、VIP记录清理、自动续费执行
  • 每日00:30：过期积分批量清理
  • 每5分钟：超时未支付订单自动关闭
  • 操作日志：管理后台关键操作全记录，支持审计追溯
  • 数据看板：仪表盘概览、短剧排行、播放趋势、观众分析、集数到达率

C面试高频问答准备

Q1: 你在这个项目中的角色是什么？

答：我是这个项目的全栈独立开发者，从0到1完成了后端架构设计、前端多端开发、数据库设计、DevOps部署配置的全部工作。后端29个API控制器、30+Service、33个数据实体均由我独立设计和实现。前端涵盖uni-app移动端、Vue 3管理后台和Vue 3官网三个子项目。同时负责Docker编排、Nginx配置、Cloudflare CDN/R2/Stream对接和自动化部署脚本编写。

Q2: 你们的支付系统是怎么设计的？如何保证幂等？

答：我们接入了4种支付渠道（Stripe、PayPal、Apple IAP、Google Play），统一通过 /api/webhooks/{channel}/notify 入口接收回调。幂等保障分三层：1）数据库层——每个渠道有唯一索引（如 stripe_payment_intent_id、google_purchase_token 等），重复回调直接被唯一约束拦截；2）应用层——PaymentEventLogService记录全链路事件，处理前先查状态；3）Webhook验签——Stripe用 webhook secret签名校验，Apple用JWT验签，Google用RTDN签名校验，确保回调来源可信。

Q3: 视频转码是怎么做的？

答：视频处理分两条路径。主路径对接 Cloudflare Stream——上传原始视频后由Cloudflare自动转码为HLS多码率流，我们通过Webhook接收转码完成通知并回写数据库。备用路径是本地FFmpeg异步转码——配置了独立的 hlsTranscodeExecutor 线程池，支持自定义核心数、最大线程数和队列容量，队列满时使用 CallerRunsPolicy 背压策略防止OOM。转码完成后生成 m3u8 播放列表，前端使用 hls.js 播放。

Q4: 认证方案为什么用自定义JWT而不是Spring Security？

答：需求上需要同时支持C端用户和管理员两套认证体系，且需要双Token（Access + Refresh）方案。自定义JWT让我能精确控制Token的payload结构（sub/role/type/jti/exp），配合Redis存储Token状态（auth:access:{jti}），既支持主动注销，又能在Refresh时验证Refresh Token是否仍然有效。整体代码量不大但控制力强，启动时还有安全校验器确保密钥长度≥32字符、生产环境禁止弱密钥。

Q5: 多语言是怎么实现的？

答：19种语言，前端和后端各有方案。后端通过 LocaleInterceptor 从请求头解析 locale，I18nService 返回对应语言的错误码和提示。前端有三套：uni-app端动态加载JSON翻译文件 + RTL方向检测；管理后台用 vue-i18n Composition API + 懒加载；共享层提取公共翻译文件和工具函数。还有一套CLI脚本（sync-i18n / export / import）用于翻译文件同步和校验，保证三端翻译一致性。

Q6: 你们的服务怎么部署的？

答：Docker Compose编排5个服务：MySQL 8（utf8mb4、健康检查）、Redis 7（AOF持久化）、Spring Boot API（依赖MySQL和Redis健康检查后启动）、admin-build（一次性Node容器构建管理后台）、Nginx（反代API + 托管前端静态文件）。Nginx配置了多子域名：srv.marastel.com(API)、dash.marastel.com(管理后台)、web.marastel.com(H5)、cdn.marastel.com(静态资源+R2代理)，全部HTTPS TLS 1.2/1.3。部署脚本用PowerShell和Shell双写，支持全量部署和增量热修复。
